I built `@secorto/i18n` to solve a very common problem in multilingual sites:
mixing content identity with routes and slugs. As the project grows, that
approach creates duplicate URLs, broken links and inconsistent navigation across
languages.

What I did was separate three concerns that usually get tangled together: the
identity of the content, the public route and the translation itself. The
library defines stable contracts for locales, sections, standalone pages and
tags, and generates reliable paths from those invariants. It also groups each
entry's variants so the app can resolve translations, draft states, missing
translations and canonical links without scattering ad hoc rules across the
codebase.

The main challenge was keeping the architecture reusable and understandable
without making it brittle. Instead of duplicating logic in each view, I
centralized the path and link generation around translation keys and route
metadata. That reduced human error and allowed the site to keep a predictable
structure as new locales and content types were added.

This work improves not only navigation but also SEO consistency,
maintainability and the overall quality of the product as the site scales.
